# CANN Recipes 英文文档翻译

将仓库中的中文技术文档翻译为英文时，严格执行以下流程。翻译的目标是忠实、完整地生成英文版本，不是改写、摘要、润色原文事实或补充背景知识。

## 与现有文档 Skill 的关系

目录分类、`zh/`/`en/`/`figures/` 的通用组织方式、`static-meta` 规范、主页 `README.md` 样例列表和最终校验流程，引用 [新增文档 Skill](./new_document_skill.md) 及其引用的 [static_meta_infos.md](../utils/references/static_meta_infos.md)。翻译质量和通用翻译流程可参考 CANN 文档仓库的[官方 translation skill](https://gitcode.com/cann/docs/blob/master/skills/translation_skill/translation_skill.md)。本 Skill 只补充当前仓库的英文翻译专属要求。

两者同时适用时，遵循以下优先级：

- 目录、文件命名、README 样例列表和校验流程遵循 `new_document_skill.md`。
- 翻译完整性、英文官方术语、英文网页链接以及中英文 `static-meta` 对照遵循本 Skill；这些更严格的翻译专属要求优先于通用表述。
- `static_meta_infos.md` 是静态字段定义、枚举和校验规则的最终依据，任何 Skill 都不得覆盖它。
- `new_document_skill.md` 允许在缺少同语言目标时链接另一语言版本并注明语言；在英文翻译任务中，按本 Skill 使用 `(Chiniese)` 标记，避免使用其他标记形式。
- 仅更新已有中文/英文文档对时，不重复新增 README 模型条目；如果本次同时新增内容目录或模型，则按 `new_document_skill.md` 更新 README 样例列表。

### 官方 translation skill 的兼容性与冲突处理

开始翻译前读取官方 translation skill 中与任务相关的章节，采用其主动语态、术语一致、语法完整、表格字段和英文风格检查建议。这些质量要求与本 Skill 兼容。以下规则存在差异时，以当前仓库规则为准：

- 官方 skill 面向通用仓库：非 `zh/` 文档通常使用同级 `<name>_en.md`；本仓库固定使用同级 `zh/` 与 `en/` 目录及相同文件名，且在缺少 `zh/` 时先创建并迁移中文文档。
- 官方 skill 通过 `exclude_docs.json` 扫描和排除文档；本仓库没有该配置约定，按实际任务指定的中文文档和仓库目录规范处理，不扫描或改动无关文档。
- 官方 skill 建议中文链接暂时保留、待后续翻译；本 Skill 要求英文目标不存在时立即保留中文链接并标记 `(Chiniese)`，不得省略标识。
- 官方 skill 的行数差异检查只能作为发现漏译的辅助信号，不能替代结构和语义逐项对照；英文因排版展开导致行数增加不视为冲突。
- 官方 skill 包含提交和推送远程仓库的流程；本 Skill 只负责生成和校验文档，不自动执行 `git commit`、`git push` 或其他未经请求的远程写操作。
- 官方 skill 没有本仓库 `static-meta` 标签同步规则；英文文档必须继续执行本 Skill 要求的“除 `sidebarTitle` 外完全一致”。

## 1. 确认源文件与目标路径

1. 完整读取中文源文档，并确认它位于内容目录的 `zh/` 下。
2. 如果中文源文档尚未位于 `zh/` 下，则先检查其所属内容目录：若 `zh/` 不存在，创建 `zh/`；随后将中文文档移动到 `zh/` 下并保持原文件名，不要在原位置保留重复副本。移动后，从新的中文文档路径重新计算并修复全部相对链接、图片路径和标题锚点。
3. 将规范化后的中文路径中的语言目录 `zh/` 替换为同级 `en/`，其余目录层级和文件名保持不变。例如：

```text
infer/llm/<model>/zh/optimization.md
-> infer/llm/<model>/en/optimization.md

cann_features/zh/prefetch_principles.md
-> cann_features/en/prefetch_principles.md
```

4. 如果同级 `en/` 不存在，则创建该目录。不要把英文文档放到仓库根目录、`zh/`、`figures/` 或其他模型/专题目录。
5. 如果目标英文文档已经存在，先完整读取并与最新中文源文档对照，再在原路径更新；不要另建带版本号、日期或 `_en` 后缀的 Markdown 文件。
6. 图片继续引用内容目录下的同级 `figures/`。中英文共用无文字图片；图片包含中文且存在 `_en` 版本时，英文文档引用对应英文图片。不得擅自新增、删除或重绘图片。

## 2. 正文翻译

正文翻译以 CANN 文档仓库的[官方 translation skill](https://gitcode.com/cann/docs/blob/master/skills/translation_skill/translation_skill.md) 为重点参考。开始翻译前，必须读取该 skill 的“读取翻译标准”及后续正文翻译规范（包括语态、时态、词汇、句子结构、语法完整性、冠词和表格字段要求）；本节将其适配到当前仓库的文档路径和元数据约束中。

逐段翻译完整文档，并遵守以下硬性要求：

- 保持原文的信息、含义、逻辑关系和技术结论，不得删减、概括、扩写或增加原文没有的解释、示例、提示、前提、结论和免责声明。
- 保持 H1/H2/H3 等标题层级、段落顺序、列表层级和编号、表格行列、引用块、折叠块、图片、公式、脚注、链接、代码块及 `static-meta` 的相对位置一致。
- 不因英文表达习惯合并或拆分内容项。可以调整单句语序和语法，但不得改变段落或列表所承载的信息边界。
- 使用正式、清晰、符合官方技术文档风格的英文。优先采用 Ascend、CANN、PyTorch、TorchAir 和相关项目官方英文文档中的术语、大小写及产品名称。
- 遵循官方 skill 的正文质量要求：主动语态优先，操作步骤使用祈使句；规律、机制和操作结果优先使用一般现在时；避免不必要的缩写、`etc.`、`e.g.`、`i.e.` 和 `via`；保持术语一致、句子结构完整、主语和谓语明确，并检查冠词和表格字段的标准译法。
- 保留 API、类名、函数名、变量名、命令、配置键、文件路径、环境变量、模型名、硬件型号和版本号，不翻译或自行改写这些标识符。
- 代码块内容原则上原样保留。仅当中文源文档中的代码注释、字符串或示例输出本身属于需要本地化的说明文字时才翻译，并确保不改变代码行为、命令含义或输出事实。
- 翻译图片替代文本、表头和链接文字，但不要修改图片文件名、锚点目标或代码中的字面值，除非本 Skill 的链接规则明确要求替换 URL。
- 不纠正原文中的技术事实、版本、数值或步骤，也不根据常识补充内容。发现疑似错误时保留原意，并在交付说明中单独报告，不写入英文正文。

## 3. 处理链接

检查中文源文档和英文目标文档中的每一个 Markdown 链接、图片引用以及 HTML `href`、`src`。

### 3.1 仓库内链接

1. 中文文档链接到本仓库的其他技术文档时，先查找目标文档的同路径 `en/` 版本。
2. 英文版本存在时，将英文文档中的链接改为从当前 `en/` 文档出发的正确相对路径。
3. 英文版本不存在时，保留指向中文文档的有效相对路径，并在英文链接后紧接标识 `(Chiniese)`。
4. 图片路径从英文目标文档所在目录重新计算，确保实际文件存在；不要直接假定中文文档中的相对路径在目标位置仍然有效。

### 3.2 外部网页链接

1. 对每个中文网页链接查找内容、产品版本和主题相同的官方英文页面。Ascend 官网链接优先使用 `https://www.hiascend.com/document/detail/en/...` 对应页面，不能只机械替换 URL 中的 `zh` 后就认定有效。
2. GitCode 或其他官方仓库文档若提供同版本 `docs/en/` 页面，改为对应英文页面；源码、配置和脚本链接不区分语言时保持原链接。
3. 只有实际确认英文页面可访问、不是 404、登录页或占位页，且内容与中文链接对应时，才替换为英文链接。
4. 没有对应英文页面时保留原中文 URL，并在英文链接后紧接标识 `(Chiniese)`。不要用非官方英文博客、搜索结果页或内容不等价的近似页面替代。
5. 保持原文链接数量及其语义用途不变。不得删除链接，也不得新增来源、延伸阅读或无原文对应的链接。

可先用以下命令列出全部待检查项，但必须逐项验证：

```powershell
rg -n "\]\(|src=|href=" <zh-document-path> <en-document-path>
```

## 4. 同步 `static-meta`

先读取中文文档末尾的完整 `static-meta`，再生成英文文档元数据：

1. 英文文档必须有且只有一个 `static-meta`，并放在文档末尾。
2. 复制中文文档的完整 `static-meta`，只将 `sidebarTitle` 的值翻译为简短、清晰且同目录不重复的英文侧栏名称。
3. 除 `sidebarTitle` 外，字段集合、字段顺序、对象结构、数组值、数组顺序和机器 ID 必须与中文文档一模一样。不得根据英文正文重新推断、增加、删除、重排或修改任何标签。
4. 中文文档没有某个字段时，英文文档也不得新增；中文文档已有字段时，英文文档不得省略。
5. `cover` 等对象字段也必须完整复制，不能用语义等价但文本结构不同的写法替代。
6. `static-meta` 的字段规范仍以 [static_meta_infos.md](../utils/references/static_meta_infos.md) 为准。若中文源文档的元数据不符合规范，先报告问题；不要在翻译过程中单方面造成中英文标签不一致。

最稳妥的做法是原样复制中文 `static-meta` 块，然后只编辑 `sidebarTitle` 的字符串值。

## 5. 一致性检查

完成翻译后，按中文和英文文档从头到尾逐项对照：

- H1 数量、标题数量及层级一致。
- 段落、列表项、表格行、引用块、图片、公式、代码块和链接数量一致。
- 所有数字、单位、版本号、参数、路径、命令和代码标识符一致。
- 每段中文内容均有对应英文内容，英文文档没有无中文来源的内容。
- 内部相对链接从英文文档路径解析后有效，标题锚点真实存在。
- 外部链接已替换为经验证的对应英文页面；无法替换的中文页面均带 `(Chiniese)` 标识。
- `static-meta` 除 `sidebarTitle` 外完全一致。
- 目标文件位于中文源文件对应的同级 `en/` 路径，文件名完全相同。

不要只依据行数判断内容一致。Markdown 换行可能不同，应以结构项和语义单元逐项对照。

## 6. 校验与交付

在仓库根目录运行：

```powershell
python utils\scripts\validate_metadata.py
```

修复由本次英文文档引入的所有校验错误。交付时说明中文源路径、英文目标路径、无法替换为英文版而保留并标记的链接，以及校验结果。
